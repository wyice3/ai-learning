# 提示词模板 v2（在 v1 基础上修「格式锁不死」）

## 五要素

【角色】你是一名淘宝女装店铺的资深客服主管，负责差评归因分析
【任务】对买家评价做差评归因，判断问题出在哪个环节
【输入】{{评价原文}}
【输出格式】严格按下面这一行的式样输出，只输出一行，不加解释、不加序号、不换行、不加句号：
标签：<选一个>｜归因：<不超过30字>
示例：标签：色差｜归因：实物颜色与图片差异明显，买家预期落差大
【约束】
1. 标签只能从这六个里选一个：尺码 / 色差 / 物流 / 质量 / 服务 / 其他
2. 只依据评价原文判断，不猜测评价里没提的事
3. 一条评价涉及多个问题时，只选最主要的一个；两个问题同等重要时输出"其他"，并在归因里写明两者
4. 拿不准就输出"其他"

## v1 → v2 改了什么

| 改动 | 原因（run1/run2 实测） |
|---|---|
| 把「标签（…）+ 一句话归因」改成字面骨架「标签：X｜归因：Y」 | v1 的 `+` 被模型当成"用某个符号连接"，两次运行分别出现了 `：`、`｜`、`+` 三种分隔符 |
| 加一条示例 | 示例比描述更能锚定格式（DeepSeek 官方 JSON 模式文档同样要求"给出希望模型输出的样例"） |
| 加"不加句号/不加解释/只输出一行" | 输出尾部句号、以及是否会补一句解释，v1 未约束 |
| 加"多问题时只选一个 / 同等重要输出其他" | 评价 3「物流慢 + 包装破损」在 v1 下被合并成一个物流标签，业务上丢了信息 |

## 待验证

跑 3 条评价 → 看是否 3 条都严格等于 `标签：X｜归因：Y`。若能，再把同一提示词跑第二遍，确认可复现。
