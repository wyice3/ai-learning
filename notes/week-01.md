- 里程碑：代码文件 → 编辑器 → 解释器 → 终端输出，**整条工具链打通**

### Day2 · 11-03（周二）：认清模型能力边界
- 实测经典"弱项题"（数字母、大数乘法、日期推算等 5 题），**全部答对**
- 结论：网上流传的"大模型不擅长 X"清单会过期，2026 年的模型靠强化学习 + 思维链补上了很多短板

- 真正还难倒它的（结构性的）：超长文本精确定位、批量打标一致性、多步长链推理、知识时效、结果不可复现

### Day3 · 11-04（周三）：第一次调用大模型 API
- 申请 DeepSeek API key，充 20 元
- key 存在 `.env` 文件里，`.gitignore` 保证它永远不上传
- `first_call.py` 跑通：让模型把一条差评归因，消耗 690 token
- 重要发现：模型名要用 `deepseek-flash`（旧名 `deepseek-chat` 已从官方文档下线）

- `stream=True` 后，回答从"等 4 秒弹一整段"变成"0.7 秒开始逐字出现"

- 产品都用流式的原因：用户等的不是答案，是"它在动"的信号
- 学会了 `reasoning_content`（思考过程）和 `content`（正文）的区别
- 学会了用 `#` 注释代码（Ctrl + / 一键注释/还原）

### Day5 · 11-06（周五）：代码上 GitHub
- `git init → add → commit → push` 四步，仓库 `wyice3/ai-learning` 上线
- `.env` 被成功挡在仓库外，key 没有泄露

## 二、本周吃到的 6 个坑（及解法）

| # | 问题 | 原因 | 解法 |
|---|------|------|------|
| 1 | 装完库仍报 `ModuleNotFoundError` | `pip` 和 `python` 不是同一个解释器 | 永远用 `python -m pip install` |
| 2 | 清华镜像装不上 openai | 镜像同步不全 | 去掉 `-i 镜像地址`，用默认源 |
| 3 | 调用报 `Model Not Exist` | `deepseek-chat` 已下线 | 模型名以官方文档为准，用 `deepseek-flash` |
| 4 | git 推不上去（证书错误） | 代理软件没接管 git，证书吊销检查失败 | `git config --global http.proxy http://127.0.0.1:7897` |
| 5 | 把 API key 粘进了 `.gitignore` | 改文件时粘错位置 | **差点把 key 传上公网**；已修正。粘敏感信息前先看清文件名 |
| 6 | `cd code` 报"找不到路径" | 已经在 code 目录里了 | 先看终端提示符里的当前路径，再决定要不要 cd |

## 三、核心概念（用自己的话）

**API key**：调用大模型的钥匙，按 token 计费。它等于钱，所以永远不进代码、不进 GitHub，只放 `.env`。

**Token**：模型处理文字的计量单位，一次问答几百到几千个。几十次调用才几分钱。

**流式（stream）**：加 `stream=True`，模型一边生成一边往外吐字。总耗时不变，但首字延迟从"整段"降到 1 秒内。

**环境变量 + .env**：程序运行时才读进来的配置。秘密（key）和代码分离，代码可以公开，秘密不能。

**Git 三板斧**：`add`（装箱）→ `commit`（封箱贴标签）→ `push`（寄出去）。以后每天改完代码就跑一遍。

**读报错**：先看最后一行（错误类型 + 原因），再往上看是哪个文件第几行。错误名是英文句子，拆开读就懂。
